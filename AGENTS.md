# Clean Code — стандарт кода проекта

Весь код пишется по философии Роберта Мартина («Чистый код»).
Каждая строка — это письмо будущему читателю.

## Именование
- Имена раскрывают намерение: `daysSinceCreation`, не `d`
- Одно слово на концепцию: не мешай `fetch`, `retrieve`, `get` для одного и того же
- Имена классов — существительные (`Customer`, `Parser`). Имена методов — глаголы (`save`, `delete`, `render`)

## Функции
- Маленькие — до ~20 строк, помещается на экран
- Делают одно дело — если можешь описать через «и», разбей
- Нет побочных эффектов — функция делает только то, что написано в её имени
- Разделяй команды и запросы — либо *делает* что-то, либо *возвращает*, но не оба действия
- Минимум аргументов — идеально 0–2, три уже подозрительно

## Комментарии
- Хороший код не требует комментариев — сначала попробуй переименовать или разбить функцию
- Недопустимо: перефразирование кода, закомментированный старый код, журналы изменений

## Обработка ошибок
- Не возвращай `null` — лучше пустой объект или исключение
- Не передавай `null` в функции

## Классы
- SRP — у класса одна причина для изменения
- Если класс описывается через «и» — разбей его

## Запахи кода — всегда рефакторить
- Длинный метод / большой класс
- Дублирование кода
- Мёртвый код (закомментированный или недостижимый)
- Цепочки вызовов (`a.b().c().d()`)

## Процесс
1. Сначала заставь работать
2. Потом сделай чистым — рефактори небольшими шагами
3. Правило бойскаута — оставь код лучше, чем нашёл
